# RapidOCR 身份证识别工作台

**离线、可校对的身份证识别桌面工具。** 拖一张身份证图片进去，自动 OCR 识别出「姓名 / 性别 / 民族 / 出生 / 住址 / 公民身份号码」六个字段，并做异常校验与可视化对照——**全程不联网，数据不出本机**。

> 基于 RapidOCR（PP-OCRv6 + onnxruntime）做文字检测识别，上层叠加了针对**身份证**的字段规则抽取与校验层，不是通用 OCR 的简单套壳。

---

## 它能做什么

| 能力 | 说明 |
|---|---|
| **身份证字段抽取** | 专为中国居民身份证设计：姓名 / 性别 / 民族 / 出生日期 / 住址 / 公民身份号码 |
| **识别异常校验** | MOD 11-2 校验位验证、出生日期与身份证内嵌日期一致性、性别与顺序码奇偶一致性、姓名合法性、关键字段缺失检测 |
| **可视化对照** | 原图与识别标注图并排显示，标注图下方条带展示抽取结果，一眼看出识别错在哪 |
| **批量识别** | 选一个文件夹批量识别，带**实时进度条**（已处理 x/N + 当前文件名） |
| **人工校对与留痕** | 字段可编辑、可重新校验；识别记录持久化，支持导出 CSV、按异常筛选、回头补正 |
| **非证件图识别** | 名片 / 证书 / 截图等非身份证图片会判为「未知类型」并留空字段，**不编造身份证号** |

**适用**：内网/离线环境下批量录入或核对身份证信息、人工复核 OCR 结果、需要留痕的证件台账场景。

## 快速开始（免编译，推荐）

到本仓库右侧 **Releases** 下载最新版压缩包（如 `RapidOCR-Desktop-v1.0.0-win64.zip`），找个目录**解压**（建议路径不含空格），然后：

1. 双击 **`RapidOCR桌面工具.exe`**
2. 会弹出一个**原生控制台窗口**，同时自动打开系统默认浏览器进入工作台
3. 在「单图模式」拖入身份证图片，即可看到识别结果

> 压缩包内**已包含 OCR 模型**（约 31MB），解压即用，**首次启动无需联网下载**。

控制台窗口说明：

- **打开 exe 即默认启用**：窗口出现时服务已自动启动并打开浏览器。
- 两个开关：运行中「启动」按钮为**灰色不可点**；停止后「停止」按钮为灰色不可点（按状态互斥）。
- **长时间运行**：关掉浏览器不会停服务，把窗口最小化即可常驻；要点「停止」或关闭窗口才真正退出。
- 附带一键启停脚本：`启动exe.bat` / `停止exe.bat`。

> **工作台在系统默认浏览器中打开**，不使用 WebView2 内嵌窗口（实测内嵌页面读不到配置信息）。控制台窗口只负责启停与状态显示。

### 环境要求

- Windows 10/11 x64
- 首次运行若无 VC++ 运行库会报错：安装微软 **Visual C++ 2019 可再发行组件（vc_redist.x64）** 即可

## 识别为什么可靠

除了 OCR 本身，系统在**规则层**和**校验层**做了针对身份证的加固：

| 环节 | 处理 |
|---|---|
| 姓名净化 | 标签前缀剥离 + 首个关键字截断 + 标签/性别词排除，并兼容 OCR 顺序错乱（姓名值跑到「姓名」标签之前）时回看上一 token |
| 序列号校验 | 公民身份号码按 ISO 7064 **MOD 11-2** 校验位验证 |
| 跨字段一致性 | 出生日期 vs 身份证内嵌日期；性别 vs 顺序码奇偶 |
| 未知类型闸门 | 非证件图判为 `doc_type="unknown"` 且字段留空，避免编造 |

**识别异常类型**：`missing`（关键字段缺失，high）/ `invalid`（字段非法，high-medium）/ `inconsistent`（跨字段不一致，medium）/ `checksum`（校验位错误，high）／兜底 `unknown`。

## 打包分发

```bat
build_exe.bat
```

产物在 `dist\RapidOCR桌面工具\`。要点：

- **exe 不打包 UI 容器**：控制台窗口用 tkinter，工作台走外部浏览器（规避 WebView2 读不到配置的问题）。
- **模型随发行包携带**：`RapidOCR.spec` 收集资源时剔除了包内的 `.onnx`，但**发行 zip 会带上运行期下载好的 `models/`**，使解压即可离线使用。
- **完全离线/气隙部署**：确保 `models/` 下有所需模型，再以 `RAPIDOCR_NO_DOWNLOAD=1` 启动即可，全程不联网。
- **端口自愈**：8003 被占用时自动顺延 8004、8005…，日志中会注明。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `RAPIDOCR_HOST` | `0.0.0.0` | 监听地址（控制台窗口模式固定 `127.0.0.1`） |
| `RAPIDOCR_PORT` | `8003` | 监听端口 |
| `RAPIDOCR_NO_GUI` | `0` | 设为 `1` 走无界面后台服务模式 |
| `RAPIDOCR_NO_BROWSER` | `0` | 设为 `1` 关闭自动打开浏览器 |
| `RAPIDOCR_NO_DOWNLOAD` | `0` | 设为 `1` 关闭自动下载模型（离线场景） |

命令行参数优先级更高：`--gui` / `--server` / `--host` / `--port`。

## 常见问题

**Q: 双击 exe 没反应 / 一闪而过？**
A: 看 exe 同目录的 `crash.log` 与 `rapidocr_app.log`。最常见是缺 VC++ 2019 运行库，装 `vc_redist.x64.exe`；其次是被旧实例占用端口（新版会自动顺延端口）。

**Q: 识别报错 / 抽不出字段？**
A: 发行包自带模型，若报模型缺失请确认解压完整（`models/` 下应有 det/rec/cls 三个 `.onnx`）。调试看 `rapidocr_app.log`。

**Q: 浏览器里的页面是我自定义的吗？会不会走网络？**
A: 前端是单文件 `static/index.html`，内联全部资源，无外链、无 CDN；服务只监听本机，**不对外发送任何数据**。

**Q: 支持营业执照吗？**
A: 规则层保留了营业执照字段抽取能力，但本工具的产品定位与界面以**身份证识别**为准。

## 技术栈

- OCR 引擎：RapidOCR 3.9.x（PP-OCRv6 / PP-OCRv4，onnxruntime）
- 后端：FastAPI + uvicorn
- 桌面窗口：Python 标准库 tkinter
- 前端：原生单文件 HTML/CSS/JS（零依赖）
- Python：3.11 ~ 3.13（构建需含 tcl/tk）

识别过程完全离线，无需任何 API Key 或第三方服务。
